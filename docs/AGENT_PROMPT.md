# コーディングエージェントへの依頼

添付の引き継ぎセットを読み、Claude認定4資格の個人用日本語問題集Webアプリを実装してください。計画を提示するだけで終わらず、ローカルで起動・検証でき、GitHub Pagesへ公開できるところまで完成させてください。今回はアプリ本体の公開を準備する依頼です。リモートへのpush、repoの公開設定変更、公開デプロイは利用者の許可を確認してから実行してください。既存の許可があれば再確認は不要です。

## 作るもの
対象：CCDV-F、CCAO-F、CCAR-P、CCAR-F。
全問題・選択肢・解説・画面・エラー・学習レポートを日本語で使えるアプリ。技術的な識別子・コマンド・ファイル名・製品名は保持する。英語原文は照合用の任意表示とし、通常の学習画面は日本語だけで完結させる。
練習、時間制限付き模擬、間違い復習、あやふや復習、ブックマーク、メモ、分野別成績、回答履歴、途中再開、パック取り込み、バックアップ復元を実装する。

## 最初にすること
1. リポジトリのAGENTS.md・既存構成を読み、このセットの全Markdown、JSON Schema、サンプルを読む。
2. 実際に添付された元教材を棚卸しする。ChatGPTのファイル名やIDだけではアクセスできないため、元ファイルの実体が無ければ未添付と報告する。外部Webサイトから全文教材を自動収集して埋め合わせない。
3. `INPUT_AUDIT.md`に存在するファイル、シート、実件数、言語、図表、欠落、利用条件を記録する。元教材不足があってもアプリとサンプルで独立して進められる作業は完了させる。
4. 提供された利用可能な教材をローカル変換し、非公開の日本語パックを作る。元データは加工せず保管する。既存Excelの件数は期待値にすぎず、実体の件数と照合する。

## 実装方針
React + TypeScript + Viteを標準案とする。IndexedDBにはDexieまたはidbなど適切な薄いライブラリを選ぶ。既存環境に合うなら同等の構成へ変更可。現在の安定版と公式ドキュメントを確認し、lockfileを残す。
バックエンド不要、サーバー不要、ランタイムのAI API不要。問題翻訳はエージェントが開発時に提供された教材から行い、利用者にAPIキーや有料翻訳サービスの契約を要求しない。
実教材はGitへ追加せず、公開ビルドにも入れない。GitHub Pagesにはアプリ本体とオリジナルサンプルだけを置く。問題・図表・原文・学習メモ・履歴は、利用者が端末で取り込むファイルとIndexedDBで扱う。
公開repoを新設する場合はclaude-study-appを候補にする。既存knowledge-publishingの公開範囲を勝手に変えない。

## 教材整理・全日本語化
`spec/DATA_AND_IMPORT.md`を実装する。旧Excelは「問題一覧」を主入力にして、同じ内容を掲載した「問題カード」「原文データ」を別の問題として取り込まない。
既存記録の目安：CCDV-F 106問、CCAR-P 126問、CCAO-F 120問、CCAR-F 120問、計472問。内訳はMatthew236問（英語）とみのるん236問（日本語）。図表50枚、CCDV-F補足講義10件。これは保存時の記録であり全問の正解保証ではない。
元資料を利用者が提供した場合に、問題・全選択肢・正解・正答理由・各誤答理由・補足・次点・次点が誤りの理由・共通背景・シナリオ・注記を省略せず翻訳／取り込む。提供のない著作物の全文転載・翻訳をURLから生成しない。
提供された資料の翻訳を小分けで進め、questionIdごとの翻訳状態と検査結果を永続化し、途中から再開できるようにする。要約で問題や選択肢を短縮しない。元の否定・条件・指定選択数・数値・コードを維持し、日本語訳で正答が変わっていないか確認する。
正解未確定、訳未完了、図欠落、原文矛盾のある問題はneeds_reviewに隔離し、通常の採点対象に混ぜない。特にMatthew CCDV-F 5.9は「1個選択」と「解答A,D」の不整合がある保存記録。コメント投稿だけで正解を断定せず、原文と注記を残して隔離する。
CCAR-Pの対応付け5問は小設問5つと候補を全て保持する。類似問題は関連付け、別教材の問題を勝手に削除しない。
変換結果を `conversion-report.json` と `IMPORT_REPORT.md` にまとめ、資格・出典・形式・翻訳状態・準備完了・隔離・不足図数を出す。472問の全件準備完了を、元データ未提供のまま主張しない。

## 画面と振り返り
スマホ幅375pxで読みやすく、ボタン44px以上、片手操作しやすい配置にする。問題→選択肢→解答確定→直下に正解と解説の順にする。解答前は説明を隠す。
練習では各問直後に解説。模擬では終了または提出まで正解を開示しない。時間・選択順シャッフル・教材混在を設定できる。
正誤だけでなく、自分の回答・正解・なぜ正解か・なぜ他が違うか・あやふや度・メモ・図表・元問題IDを一画面で確認する。最後の正誤だけで過去の履歴を上書きしない。
要件詳細は `spec/APP_REQUIREMENTS.md` を受け入れ基準として使う。

## パックとデータ保全
JSON Schema準拠のUTF-8日本語JSONと、図表を同梱するZIPパックに対応する。ZIP内はpack.jsonとassets/のローカル画像だけ。Excel→JSON/ZIP変換は開発用のローカルCLIとし、Webアプリの必須依存を増やし過ぎない。
パックの解析・検証が完全に成功してからIndexedDBへトランザクション保存する。失敗時は既存データを保つ。ID・revision・本文ハッシュを使って再取り込みを冪等にする。
画像もバックアップへ含め、復元後に参照切れしないようにする。セッションと回答のID、UTCタイムスタンプ、JSTの日付表示、旧問題のスナップショットを保持する。
私的パックや履歴をサーバー、ログ、解析サービス、GitHubへ送らない。importしたHTMLやMarkdownは安全に描画し、任意スクリプト・外部画像・不正ZIPパスを実行／取得しない。

## GitHub Pages
repoサブパス対応のVite base、hash routingまたは同等のリロード対策、相対asset URLを設定。Actionsで型検査・意味のあるテスト・buildに成功した成果物だけをPagesへ送る。Pagesの公開に必要な最小権限を指定する。
GitHubの無料枠の公開repoで運用する。独自ドメインや有料サービスは要求しない。private repoのPagesが無料で使えるとは説明しない。クライアントだけのログイン画面を非公開化として扱わない。
可能ならPWA化し、静的アプリのみキャッシュする。初回読み込みとパック取り込み後、オフライン学習できる。更新しても履歴を消さない。SW更新通知、DBバージョン移行、旧assetキャッシュの整理を安全に行う。

## 必須成果物
- 起動できるアプリ、lockfile、Pagesのworkflow、元データ用.gitignore
- 日本語README（起動・検証・パック作成・取り込み・復元・Pages設定・端末移行）
- ローカル変換CLI、Schema検証、変換報告、問題ID/図表ID対応表
- 実教材が提供され利用可能なら、Git外のdist-private/へ資格別日本語パックと全資格パック。公開用distとは分ける。
- 未提供ファイル・未翻訳・未検証・隔離一覧。実教材不足なら、動くアプリ＋オリジナルサンプル＋不足一覧で状態を明示する。
- テスト結果、375px/PC画面のスクリーンショット、最終HANDOFF.md

## 完了条件
`spec/ACCEPTANCE.md`の実装・教材・公開の3段階を別々に判定する。利用者の許可がある場合は実URLまで確認。承認待ちや権限不足なら、実行可能な最後の手順まで準備し、未公開と明示する。
不必要な確認で止めず、仕様に沿って合理的な選択を行う。実装できたこと、試験したこと、不足する入力、最終URLと未実施事項を簡潔に報告する。
